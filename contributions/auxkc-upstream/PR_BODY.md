An AuxKC rebuild currently enumerates `/Library/Extensions/*.kext` only. An existing collection can also include registered bundles outside that directory: on one Raptor Lake-HX system, `kmutil inspect --show-extension-info` listed AppleMobileDevice under `/Library/Apple/System/Library/Extensions`. A rebuild that omits that explicit input can silently remove an existing member.

The shared shell helper now reads the existing auxiliary section, carries those external bundle paths into `kmutil create -p`, and checks the candidate auxiliary section for the exact preserved bundle ID and version before the existing replacement step. Missing bundles, inspection failure, malformed member rows and absent identities stop replacement. Both inspections use the same strict parser: only the exact `Extension Information:` header, blank lines and validated three-field member rows (with an optional trailing tab) are accepted inside the auxiliary section. Unrecognized nonempty lines, extra fields, duplicate auxiliary sections and noncanonical paths fail closed. Inputs under `/Library/Extensions` continue to come from the current directory, allowing the installer/uninstaller to replace or remove its own local components. The standalone uninstaller stays synchronized with the shared helper. This adds no Python dependency to installed scripts.
