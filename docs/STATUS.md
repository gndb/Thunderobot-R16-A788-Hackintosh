## 仍未解决或未验收

| 项目 | 当前判断与下一步边界 |
| --- | --- |
| 冷启动首次显示接管 | 仍有黑屏记录。显示恢复 / 重新 modeset 后出现过画面，本机显示重试补充也有实际执行记录；具体故障不能只归因于加速器或只凭等待时间确定。 |
| 熄屏 / 变暗后无法唤显 | 用户已遇到点击、按键后不能恢复画面并强制关机。已有恢复候选仍未得到稳定验收，不能标为已修复。 |
| 整机睡眠 / 合盖 / 休眠 | 未完成可靠恢复与待机耗电验收。显示 Doze / Wake 与整机 S3 是不同测试。 |
| 240 / 300 Hz、DSC / HDR / VRR | 当前高刷代码与两个实验启动参数已退出。曾在一个 macOS 会话中切到 240 Hz 并看到正常画面，随后冷启动出现黑屏；不作为可发布的稳定高刷功能。 |
| 后置 USB-C 数据 | 同接口在 Windows 可用，但 macOS 连接外置硬盘、两种方向均反馈无反应；尚未修好。HS02 / SS02 已列入映射，单纯更改端口名或电流属性不是已验证修复。 |
| Type-C 给电脑充电 | 用户确认同一充电器 / 同一线缆在 Windows 能充电；macOS 接入时未识别外接电源。记录为 `ExternalConnected=false` 和 Battery Power，不只是满电停止充电。尚未直接测得 VBUS、PD 合同或实际功率，不能断言协商已经失败，也不能把软件显示的 60 W 当作实测 PD 限额。 |
| USB / PD 电源补丁 | 本机此前尝试恢复父 XHCI 电源表的改名补丁已退出。它可能影响父控制器和外置系统盘，不等于后置单口或 140 W PD 修复；不盲目重开、写 GPIO 或伪造 `_PSR=1`。 |

| 摄像头 | 已有设备 / 服务记录，但没有足以确认稳定采帧、全部格式和睡眠恢复的验收。 |
| 外屏 / HDMI / USB-C 视频 / TB / USB4 | 逐接口显示与热插拔未完成。PD 输入、USB 数据、DP Alt Mode 和 Thunderbolt PCIe 是不同能力，不能互相替代。 |

## 2026-11-13 的双 GPU 新试验

04:37 UTC 的另一个配置只删除了 `-nvoff`，允许已有系统侧 NVIDIA 驱动与 WhateverXe 同时尝试初始化。它保留核显、亮度、无线、USB 和高刷关闭状态，没有升级 NVIDIA 驱动，也没有启用 `nmhybrid` / `NMIntelFB`。

**当前尚无该配置重启后的实机结果，不属于本次“已成功”基线。** 双显卡被枚举、NVIDIA Metal 可用、WindowServer 选择哪块 GPU，以及内屏实际出现画面，应分别验证。不能把此前 NVIDIA 独显直连成功或 A788 单独成功合并成双 GPU 共同输出已经成功。

## 使用与发布边界

- 请先核对 [HARDWARE.md](HARDWARE.md)，生成自己的 SMBIOS 标识，并保留可以恢复的原 EFI。
- 核显与 NVIDIA 历史路线都依赖 EFI 之外的系统侧组件，公共 EFI 本身不是完整图形栈安装器。
- 本仓库记录社区实验适配，不是 Apple 官方硬件支持，也没有跨机型兼容承诺。
- 不公开机器序列号、MAC、系统卷 UUID、私人路径、原始完整 NVRAM / IORegistry 或含标识的历史 config 副本。
